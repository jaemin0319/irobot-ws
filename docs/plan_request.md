# Claude Code Plan 모드 요청: MuJoCo 프랑카 reach–home 시뮬레이션

MuJoCo에서 프랑카 로봇팔이 매 사이클 새 랜덤 목표점에 도달하고, 미리 정한 home 관절 자세로 실제 제어를 통해 복귀하는 시뮬레이션을 만들고 싶습니다. 지금은 **Plan 모드에서 환경과 자료를 확인하고 구현 계획만 작성하세요. 구현은 시작하지 마세요.**

## 1. 이번 단계의 범위

- 실제 작업 PC에서 읽기 전용으로 환경, 작업공간과 기존 파일을 확인하고 공식 모델 출처를 조사하세요.
- 코드 작성·수정, 패키지 설치, 가상환경 생성, 모델 다운로드·변환, 시뮬레이션 실행은 후속 구현 단계의 계획으로 남기세요.
- 확인한 사실, 아직 확인하지 못한 사항, 제안하는 조건을 구분하세요. 확인하지 않은 환경이나 실행 결과를 추측해서 성공으로 보고하지 마세요.
- 반드시 사용자 결정이 필요한 사항은 질문하고, 모델을 확인하면 정할 수 있는 기술적 조건은 근거와 함께 제안하세요. 미정 조건을 조용히 확정하지 마세요.

## 2. 전용 작업공간: `~/irobot_ws`

작업공간은 **실제 작업 PC에서 Claude Code를 실행하는 사용자의 홈 디렉터리 아래 `~/irobot_ws`**입니다. 다른 PC나 임시 실행 환경의 홈 경로로 대체하지 마세요.

1. 실제 사용자와 홈 경로를 확인하고 `~`를 확장한 절대 경로를 보고하세요.
2. 홈 디렉터리와 작업공간의 접근 권한, 소유자, 해당 파일시스템의 디스크 여유를 확인하세요. 경로가 심볼릭 링크이거나 일반 디렉터리가 아니면 실제 대상과 사용 가능 여부를 확인하세요.
3. `~/irobot_ws`가 이미 있으면 기존 코드, 가상환경, 모델, 문서, 로그 및 작업 지침을 확인하여 재사용할 항목과 새로 필요한 항목을 구분하세요. 기존 파일을 삭제하거나 덮어쓰지 마세요.
4. 경로가 없으면 부모 경로의 생성 가능 여부를 확인하고, **구현 단계에서 생성**하도록 계획하세요. Plan 단계에서는 생성하지 마세요.
5. 프로젝트 코드, 가상환경, 모델·메시, 문서, 실행 로그는 모두 이 작업공간 안에서 관리하도록 디렉터리 구조를 제안하세요. 모델 변환 산출물과 프로젝트에서 지정하는 다운로드·패키지 캐시도 가능한 한 이 안에 두세요.
6. 필요한 저장공간을 추정하고, 무한 반복 실행의 로그가 계속 커지지 않도록 로그 회전 또는 크기 제한을 계획하세요. 프로젝트 때문에 작업공간 밖에 설치·변경이 필요한 항목이 있으면 필요성과 대안을 따로 설명하세요.

## 3. 실제 PC 환경 확인과 준비 계획

실제 PC의 OS·아키텍처, Python 버전과 실행 경로, 기존 가상환경, MuJoCo 설치 여부·버전, 관련 의존성, GUI/OpenGL 사용 가능 여부를 확인하세요. 현재 셸과 기존 Python 환경을 확인하되, 확인을 위해 새 설치나 환경 변경은 하지 마세요.

확인 결과를 바탕으로 사용할 Python 환경, 의존성 설치 방법, GUI 실행 방법과 실행 명령을 계획하세요. 기존 환경을 재사용할지 `~/irobot_ws` 안에 전용 가상환경을 만들지 근거를 제시하세요. 호환성이나 설치 가능 여부가 불확실하면 검증 방법을 남기세요.

## 4. 프랑카 모델 확보 계획

프랑카 모델의 **URDF/Xacro와 필요한 메시를 공식 출처에서 찾아 확보하는 작업도 Claude Code가 담당**하도록 계획하세요.

- 사용 가능한 프랑카 기종과 공식 제조사 모델 저장소·문서를 조사하고, 선택할 기종과 이유를 제안하세요. 기종 선택이 사용자 의도에 영향을 주면 질문하세요.
- 출처 URL, 모델 파일, 메시 의존성, 라이선스, 버전·커밋 고정 방법을 기록하세요.
- Xacro 전개와 패키지 경로 처리, URDF를 MuJoCo에서 사용할 모델로 변환·보완하는 절차를 확인하세요. 관절 제한, 관성, 충돌 형상, 액추에이터, 엔드이펙터 기준점이 올바르게 반영되는지 검증할 방법을 포함하세요.
- 별도의 MuJoCo 모델 저장소를 활용할 경우 제조사 공식 자료와 구분하고, 원본 URDF/Xacro·메시와의 관계 및 수정 내용을 설명하세요.
- 단순히 모델을 화면에 띄우는 것과, 물리 시뮬레이션에서 제어 가능한 상태로 준비하는 것을 각각 확인하도록 계획하세요.

## 5. 원하는 최종 동작

다음 순서로 동작해야 합니다.

**MuJoCo 실행 → 프랑카 로드 → 초기 home 확인 → 유효한 새 랜덤 목표 생성 → reach → 도달 확인 → home 복귀(recovery) → 복귀 확인 → 다음 랜덤 목표 생성**

- **반복 횟수 제한 없이 사용자가 종료할 때까지 계속 실행**해야 합니다. 최종 실행의 기본값에 최대 사이클 수를 두지 마세요.
- 창 닫기와 터미널 종료 명령(예: Ctrl+C)을 처리해 시뮬레이션·뷰어·로그 자원을 정상적으로 정리하도록 계획하세요. 각 단계에서도 종료 요청을 받을 수 있어야 합니다.
- 목표 마커와 로봇의 움직임이 화면에 보이면 됩니다. 복잡한 UI는 필요하지 않습니다.
- 검증용 고정 목표 실행과 최종 랜덤 반복 실행을 구분하세요. 고정 목표는 최초 검증에만 사용하며 최종 동작을 고정 목표 반복으로 대체하지 마세요.

## 6. home과 recovery의 의미

- **home:** 모델 기준으로 미리 정한 관절 자세입니다.
- **recovery:** 현재 관절 상태에서 제어 입력과 물리 시뮬레이션을 통해 그 home 자세까지 실제로 움직여 돌아오는 동작입니다.
- 초기 모델 로딩 시 시작 자세를 설정하는 것은 별도로 설명하되, reach 이후 복귀를 관절값 직접 대입, 순간 이동, 상태 reset, keyframe 복원 등으로 대신하지 마세요.
- home에 엔드이펙터 위치만 맞는 것으로는 부족합니다. 지정한 home 관절 자세와 실제 관절 상태를 비교해 복귀를 판정하세요.
- **home 복귀가 확인되기 전에는 다음 목표를 생성하지 마세요.** 다음 목표를 미리 샘플링하거나 대기열에 쌓는 방식도 사용하지 마세요.

## 7. 랜덤 목표 생성과 제어 계획

- 각 사이클의 home 확인 후 새 목표를 랜덤으로 생성하세요. 미리 정한 몇 개의 점을 순서대로 반복하는 방식은 원하지 않습니다.
- 좌표계와 엔드이펙터 기준점을 명시하고, 실제 모델의 관절 제한과 작업공간에 맞는 목표 범위·분포를 제안하세요.
- 공간 범위 안에 있다는 이유만으로 도달 가능하다고 가정하지 마세요. IK 또는 관절 공간 샘플링 후 FK 등 적절한 방법을 선택하고, 도달 가능성·관절 제한·충돌·제어 경로의 유효성을 어떻게 확인할지 설명하세요.
- 유효하지 않은 후보는 실제 reach에 들어가기 전에 제한된 횟수로 재샘플링할 수 있습니다. 유효 목표 생성에 계속 실패하면 중단하고 이유를 알리도록 계획하세요. 무한 후보 탐색으로 멈춘 것처럼 보이게 하지 마세요.
- 목표는 위치만 지정할지, 엔드이펙터 방향도 제한할지 질문하거나 제안하세요. 방향 조건을 조용히 추가하지 마세요.
- 사용할 IK·궤적 생성·제어 방법을 제안하고, 급격한 움직임 없이 reach와 recovery를 수행하는 방법을 설명하세요. 목표 관절값을 계산하는 것과 실제 제어로 이동하는 것을 구분하세요.
- 재현용 seed 설정은 제공할 수 있으나, 실행 중 매번 seed를 초기화해 같은 목표만 만들지 마세요.

## 8. 상태 기반 성공 판정과 실패 처리

일정 시간이 지났다는 이유로 도달 또는 복귀를 성공 처리하지 마세요.

- **초기 home 확인:** 실제 관절 위치와 속도를 기준으로 시작 준비 상태를 확인하세요.
- **reach 성공:** 현재 엔드이펙터 위치와 목표의 오차를 기준으로 판정하고, 실제 관절 위치·속도와 제한 준수 여부도 확인하세요. 방향을 제어하기로 했다면 방향 오차도 포함하세요.
- **recovery 성공:** 현재 관절 위치와 home 관절값의 오차 및 관절 속도를 기준으로 판정하세요.
- 목표를 지나가는 순간을 성공으로 오인하지 않도록, 상태 기준을 일정 시간 유지하는 안정화 조건을 제안하세요. 유지 시간만 채웠다는 이유로 상태 오차를 무시해서는 안 됩니다.
- 시간 제한은 성공 조건이 아니라 실패 감지 기준으로만 사용하세요. 시뮬레이션 시간과 실제 경과 시간을 구분하고, 시뮬레이션 정지·뷰어 문제 등의 감지 방법도 제안하세요.
- 초기 home 확인, 목표 생성, reach, 도달 확인, recovery, 복귀 확인 중 어느 단계라도 실패하면 **자동 반복을 중단**하세요. 다음 단계나 다음 목표로 넘어가거나 자동 reset으로 실패를 숨기지 마세요.
- 실패 시 현재 단계, 목표, 관절 상태, 위치·관절 오차, 경과 시간, 확인된 원인과 추정 원인을 구분해 화면 또는 터미널과 로그에 남기세요. 실패 후 정지·종료 처리도 계획하세요.

## 9. 구현 순서와 단계별 확인 방법

다음 순서를 기본으로 구체적인 구현 계획을 작성하세요.

1. 실제 환경과 `~/irobot_ws` 점검, 기존 항목 재사용 판단.
2. 구현 단계에서 작업공간·가상환경·의존성 준비.
3. 공식 모델·메시 확보, 변환 및 MuJoCo 모델 검증.
4. 뷰어 실행, 로봇·목표 마커 표시, 초기 home 확인.
5. **고정 목표 한 점으로 reach → 상태 기반 도달 확인 → 실제 제어 recovery → 상태 기반 home 복귀 확인.**
6. 위 검증을 통과한 뒤 유효 랜덤 목표 생성과 무한 반복 상태 전이 연결.
7. 실패 시 중단, 창 닫기·Ctrl+C 정상 종료, 로그 기록 검증.

각 단계에 선행 조건, 필요한 작업, 확인할 관측값, 통과 기준, 실패 시 조치를 포함하세요. 최초 고정 목표 검증을 통과하기 전에 랜덤 반복 구현·검증으로 넘어가지 마세요. 검증 세션은 유한한 관측 구간으로 수행할 수 있지만, 최종 프로그램의 반복 횟수를 제한하는 방식으로 구현하지 마세요.

## 10. 아직 정하지 않은 조건과 최종 계획 보고 형식

다음 조건은 제가 아직 확정하지 않았습니다. 실제 모델과 환경을 확인한 뒤 질문 또는 근거 있는 제안으로 정리하세요.

- 프랑카 기종, 그리퍼 포함 여부와 고정 상태.
- home 관절값과 각도 단위.
- 엔드이펙터 기준점, 목표 좌표계, 랜덤 목표 범위·분포.
- 위치만 제어할지 방향도 제어할지.
- 고정 검증 목표 한 점.
- 위치·관절·속도 허용 오차, 안정화 유지 시간, 단계별 시간 제한.
- 제어 속도, 제어 주기와 물리 시뮬레이션 시간 간격.

최종 계획에는 다음을 담아 주세요.

1. 실제 PC와 작업공간에서 확인한 사실 및 미확인 항목.
2. 공식 모델 출처와 확보·변환·검증 방법.
3. `~/irobot_ws` 내부 디렉터리 구조와 환경 준비 절차.
4. 상태 전이, 제어 방법, 랜덤 목표 유효성 검사, 성공·실패 판정.
5. 고정 목표 검증부터 랜덤 무한 반복까지의 구현 순서와 통과 기준.
6. 구현 후 사용할 실행·검증·종료 명령과 확인할 로그 항목.
7. 사용자에게 필요한 질문, 제안 기본값과 선정 근거, 남은 불확실성.

**이번 응답은 계획 보고로 마무리하세요. 계획을 제출한 뒤 스스로 구현에 착수하지 마세요.**
